## 1. Quick Start

### Prerequisites

- Docker 24+ and Docker Compose 2.20+
- Node.js 18+ (optional, for development mode)
- 8GB RAM minimum (4GB for Docker-only demo)
- 10GB free disk space

### Start the Demo Environment

```bash
# Clone the repository
git clone <repository-url>
cd Enterprise-Cyber-Security-Platform

# Copy the demo environment file
cp .env.example .env

# Start all services
docker compose up -d

# Wait for services to become healthy
docker compose ps

# Seed demo data
docker compose exec backend npm run seed:demo

# Access the application
# Frontend: https://localhost
# Backend API: https://localhost/api
# Grafana: http://localhost:3001 (admin / demo-grafana-2024)
```

### Development Mode (Alternative)

```bash
# Backend
cd backend
cp .env.example .env
npm install
npm run seed:demo
npm run dev

# Frontend
cd ../frontend
cp .env.example .env
npm install
npm run dev
```

Access at `http://localhost:5173`

## 4. Mock Security Events

The demo mode injects mock security events into the dashboard to simulate a live SOC environment.

### Mock Events Timeline

| Time | Event Type | Severity | Description |
|------|-----------|----------|-------------|
| T+0m | Login | INFO | Demo user logged in from 192.168.1.100 |
| T+2m | URL Scan | INFO | URL scan completed — example.com (safe) |
| T+5m | Email Analysis | WARNING | Phishing email detected from unknown sender |
| T+8m | File Scan | CRITICAL | Suspicious file uploaded — 2 engines flagged |
| T+12m | Threat Intel | WARNING | New CVE-2024-XXXXX published |
| T+15m | UEBA Alert | MEDIUM | Anomalous login from new location |
| T+18m | Cloud Finding | HIGH | S3 bucket publicly accessible |
| T+22m | Container Scan | MEDIUM | Outdated base image detected |
| T+25m | K8s Finding | HIGH | Pod running with privileged security context |
| T+30m | AI SOC Recommendation | INFO | AI recommends blocking IP 10.0.0.99 |

### How Mock Events Work

1. Mock events are generated by the `demoEventGenerator` service in the backend.
2. Events are injected into the database with the `demo` tag.
3. The dashboard displays these events alongside real-time data.
4. All mock events are clearly labeled with a `[DEMO]` badge.
5. No real external API calls are made for mock events.
6. Mock events can be cleared with `docker compose exec backend npm run seed:demo -- --clear-events`.

## 7. Safety Guidelines

### What is NOT in the Demo

- No real secrets or credentials
- No production data
- No real threat intelligence feeds
- No real VirusTotal, AbuseIPDB, or OTX API calls
- No real email sending (SMTP is disabled in demo mode)
- No real AI provider API keys required (Ollama runs locally)
- No external network calls for mock events

### Safety Features

| Feature | Description |
|---------|-------------|
| Demo Mode Toggle | Clearly indicates when demo mode is active |
| [DEMO] Badges | All demo content is visually marked |
| No External API Calls | Mock events use local data only |
| No Real Secrets | Demo credentials are pre-configured and clearly marked |
| No Production Data | All data is synthetic and generated for demo purposes |
| Network Isolation | Demo environment uses Docker internal network only |
| Read-Only Database | Demo seed script marks all data with `isDemo: true` flag |

### Emergency Stop

If the demo needs to be stopped immediately:

```bash
# Stop all services
docker compose down

# Clear demo data (optional)
docker compose exec backend npm run seed:demo -- --clear

# Remove all volumes (destroys all data)
docker compose down -v
```
